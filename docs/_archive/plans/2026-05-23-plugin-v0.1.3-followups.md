## 1. Citation regex too narrow

`[x]` **Shipped in marketplace PR #3 (v0.1.3).**

**Where.** `plugins/make-skills-discipline/scripts/pre_tool_use.py:42-44`.

```python
CITATION_REGEX = re.compile(
    r"[a-zA-Z_/\\.\-]+\.(py|ts|tsx|jsx|js|md|json|yaml|yml|toml|sh|ps1|sql):\d+"
)
```

**Problem.** The regex only matches `path/file.ext:line`. When the agent cites:
- a Context7 docs URL (`https://grafana.com/docs/loki/...`)
- a GitHub URL (`https://github.com/anthropics/...`)
- a bare file path without a line number (sometimes appropriate when citing a config file as a whole)

…the `has_recent_citation()` check still returns False and `CITATION_REMINDER` fires. False positives observed multiple times during the wrapper-research turns of the 2026-05-22 session.

**Definition of done.**

1. Extend `CITATION_REGEX` (or add a second pattern) to accept:
   - `https?://[^\s]+` URLs
   - bare paths in the form `path/to/file.ext` (still requires the extension to filter out arbitrary slashed strings)
2. Add a test in `plugins/make-skills-discipline/tests/` that covers a transcript with only a URL citation — should NOT trigger the reminder.
3. Bump plugin version in `plugin.json` to `v0.1.3`.
4. Update the v0.1.2 → v0.1.3 changelog entry in the marketplace plugin README or CHANGELOG.

**Estimated effort.** 30 minutes including the test.

### 1a. Dual-mode triggers fire on docs that merely mention the keywords

`[x]` **Shipped in marketplace PR #3 (v0.1.3) — bundled with #1.**

**Definition of done.** Same as #1 — include in v0.1.3. Add a test for "write to a docs file mentioning AUTH_SECRET" → should NOT fire.

## 2. Layered-explanation discipline not hook-enforced

`[ ]` **v0.1.3 candidate — fuzzy, higher risk.**

**Background.** `skills/layered-explanation/SKILL.md` (landed via #39) describes the four-layer pattern: ELI5 → quick reference → depth → mental model. The skill is descriptive; no hook detects when the agent is explaining infrastructure / architecture / tooling in a jargon-dense single layer.

**Possible approach.**

A `Stop` hook (fires after each assistant turn ends) that:
1. Reads the last assistant message from the transcript.
2. Heuristic: looks for tokens that indicate an infra/tooling explanation (`OpenTelemetry`, `Promtail`, `JWT`, `webhook`, `MCP`, `LangGraph`, `LanceDB`, etc.) AND length > N words.
3. If matched and no headers/structure detected (no `###`, no bullets, no obvious tiered breakdown), injects a soft reminder via `additionalContext` for the NEXT turn: "Previous explanation looked jargon-dense — consider the four-layer pattern next time."

**Risk of false positives.** High. Many explanations are appropriately single-layer (e.g., quick answers to simple questions). The heuristic needs careful tuning to avoid nagging.

**Alternative.** Don't enforce; document the discipline in the discipline-skill `SKILL.md` text and trust the skill-injection at session start to remind. Skip the hook entirely until friction is observed in the wild.

**Recommendation.** **Defer.** Document in the discipline `SKILL.md` only. Add the hook later if the skill alone proves insufficient.

## 6. `_observability.py` import silently fails under Node launcher

`[ ]` **NEW from smoke test — v0.1.4 candidate.**

**Where.** `plugins/make-skills-discipline/scripts/pre_tool_use.py:32-40` (same pattern in `user_prompt_submit.py`, `stop_audit.py`, `session_start.py`).

```python
sys.path.insert(0, str(Path(__file__).resolve().parent))
try:
    from _observability import log_event, now_ms
except Exception:  # noqa: BLE001
    def log_event(*_args, **_kwargs): pass
    def now_ms() -> int: return int(time.time() * 1000)
```

**Problem.** When Claude Code invokes the hook via the Node launcher (`run-python.mjs`), the `from _observability import log_event` line fails silently — caught by the `except Exception: pass` — and the script falls back to the no-op `log_event` stub. Result: `~/.claude/logs/hooks.jsonl` (or `${CLAUDE_PROJECT_DIR}/.claude/logs/hooks.jsonl`) is never written.

**Evidence.**

- Smoke-test verified that `pre_tool_use.py` IS executing as v0.1.3 (the docs gate skipped the throwaway file — that gate doesn't exist in v0.1.0).
- Manual `python -c "from _observability import log_event; log_event(...)"` invocation, with `sys.path` set to the same cache dir, writes to `~/.claude/logs/hooks.jsonl` exactly as expected.
- Result file from the manual call: `{"ts":"2026-05-24T03:09:53...","hook":"SmokeTest","phase":"end","action":"manual_probe","note":"direct call"}` — proves the write path, mkdir, and JSON serialization all work.
- After the manual call's file was deleted, no subsequent hook fire recreates it. The actual hook-invoked path silently falls through to the no-op stub.

**Hypothesis.** When `run-python.mjs` invokes the Python script as `python /full/path/to/pre_tool_use.py`, the script's `__file__` may resolve in a way that breaks `sys.path.insert(0, str(Path(__file__).resolve().parent))` on Windows — or there's a stdin/stdout interaction with the spawned process that interferes with the import (less likely; imports happen before stdin read).

**Implication.** PR #38's Loki dashboard panels will stay empty until this is fixed. The dev-experience observability layer technically works end-to-end *if* the file gets written — but right now it isn't.

**Definition of done.**

1. Reproduce the import failure with a minimal test (small Node script invoking `python /path/to/pre_tool_use.py` with stdin JSON, observe whether `hooks.jsonl` gets written).
2. Replace the silent `except Exception: pass` with at least one of:
   - **a.** Use `importlib.util` to load `_observability` from an absolute path computed from `os.path.dirname(os.path.abspath(__file__))` — bypasses `sys.path` entirely.
   - **b.** Inline the `log_event` function into each hook script — eliminates the import.
   - **c.** Keep the try/except but log the failure to a fallback file (`~/.claude/logs/hook-import-errors.log`) so the failure is observable instead of silent.
3. Add a test to `tests/test_pre_tool_use.py` that runs `pre_tool_use.py` as a subprocess (mirroring the Node launcher's invocation pattern) and confirms a log entry lands.
4. Bump plugin to v0.1.4.

**Estimated effort.** 1-2 hours including the reproducer and the subprocess test.
