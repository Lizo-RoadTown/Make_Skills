## 1. Citation regex too narrow

`[x]` **Shipped in marketplace PR #3 (v0.1.3).**

**Where.** `plugins/make-skills-discipline/scripts/pre_tool_use.py:42-44`.

```python
CITATION_REGEX = re.compile(
    r"[a-zA-Z_/\\.\-]+\.(py|ts|tsx|jsx|js|md|json|yaml|yml|toml|sh|ps1|sql):\d+"
)
```

**Problem.** The regex only matches `path/file.ext:line`. When the agent cites:
- a Context7 docs URL (`https://grafana.com/docs/loki/...`)
- a GitHub URL (`https://github.com/anthropics/...`)
- a bare file path without a line number (sometimes appropriate when citing a config file as a whole)

…the `has_recent_citation()` check still returns False and `CITATION_REMINDER` fires. False positives observed multiple times during the wrapper-research turns of the 2026-05-22 session.

**Definition of done.**

1. Extend `CITATION_REGEX` (or add a second pattern) to accept:
   - `https?://[^\s]+` URLs
   - bare paths in the form `path/to/file.ext` (still requires the extension to filter out arbitrary slashed strings)
2. Add a test in `plugins/make-skills-discipline/tests/` that covers a transcript with only a URL citation — should NOT trigger the reminder.
3. Bump plugin version in `plugin.json` to `v0.1.3`.
4. Update the v0.1.2 → v0.1.3 changelog entry in the marketplace plugin README or CHANGELOG.

**Estimated effort.** 30 minutes including the test.

### 1a. Dual-mode triggers fire on docs that merely mention the keywords

`[x]` **Shipped in marketplace PR #3 (v0.1.3) — bundled with #1.**

**Where.** `pre_tool_use.py:60-70` (`DUAL_MODE_TRIGGERS`) + `pre_tool_use.py:89-91` (`touches_dual_mode`).

**Problem.** `touches_dual_mode()` json-dumps the entire `tool_input` and substring-searches for trigger keywords. Triggers on a Write to a docs file that merely mentions `AUTH_SECRET` or `JWTTenantResolver` (e.g., this very planning doc fired the hook). Same class of false-positive as the `memory`/`tenant` issue that v0.1.2 fixed.

**Fix candidates.**

- Gate the check on file extension (skip `.md`, `.rst`, `.txt`).
- Gate the check on path (skip `docs/`, `README.md`, anything not under `platform/` or `web/`).
- Both. Probably both.

**Definition of done.** Same as #1 — include in v0.1.3. Add a test for "write to a docs file mentioning AUTH_SECRET" → should NOT fire.

## 2. Layered-explanation discipline not hook-enforced

`[ ]` **v0.1.3 candidate — fuzzy, higher risk.**

**Background.** `skills/layered-explanation/SKILL.md` (landed via #39) describes the four-layer pattern: ELI5 → quick reference → depth → mental model. The skill is descriptive; no hook detects when the agent is explaining infrastructure / architecture / tooling in a jargon-dense single layer.

**Possible approach.**

A `Stop` hook (fires after each assistant turn ends) that:
1. Reads the last assistant message from the transcript.
2. Heuristic: looks for tokens that indicate an infra/tooling explanation (`OpenTelemetry`, `Promtail`, `JWT`, `webhook`, `MCP`, `LangGraph`, `LanceDB`, etc.) AND length > N words.
3. If matched and no headers/structure detected (no `###`, no bullets, no obvious tiered breakdown), injects a soft reminder via `additionalContext` for the NEXT turn: "Previous explanation looked jargon-dense — consider the four-layer pattern next time."

**Risk of false positives.** High. Many explanations are appropriately single-layer (e.g., quick answers to simple questions). The heuristic needs careful tuning to avoid nagging.

**Alternative.** Don't enforce; document the discipline in the discipline-skill `SKILL.md` text and trust the skill-injection at session start to remind. Skip the hook entirely until friction is observed in the wild.

**Recommendation.** **Defer.** Document in the discipline `SKILL.md` only. Add the hook later if the skill alone proves insufficient.

## 4. Stacked-PR auto-close friction

`[ ]` **Optional — low priority.**

**Observed during 2026-05-23 merge queue.** GitHub auto-closes stacked PRs when their base branch is deleted on merge. Bit me twice:

- #37 (base: `phase-a-ci-and-observability`) → auto-closed when #35 merged. Recreated as #40.

**Possible fixes.**

- **A: SessionStart reminder.** Plugin adds a tip when it detects open stacked PRs in the current repo. Requires a `gh` call at session start — adds latency.
- **B: Workflow.** Pre-merge retargeting: before merging the base PR, retarget any stacked PRs to `main` (or to the next base in the stack). Manual discipline, no plugin change.
- **C: Slash command.** `/discipline-rebase-stacked-prs` that lists stacked PRs and offers to retarget them.

**Recommendation.** **B for now.** Document the discipline in `CLAUDE.md` or the discipline `SKILL.md`. If the friction recurs, build C.
