### Fixed

- **Add explicit `httpx>=0.27` to `platform/requirements.txt`** — fixes startup crash introduced by PR #71. PR #71's `services/skill_making/ack_sender.py` imports `httpx` for the registration-ack POST, but `httpx` was not declared as a direct dependency (it was a transitive dep of langchain). When `services/api/main.py` imports `compile_worker` → `ack_sender` → `httpx`, the deployed container's startup failed with ImportError and Render's load balancer returned 502 on all routes. Verified the failure mode via `https://make-skills-api.onrender.com/healthz` and `/bridge/promotion-candidate` both returning 502 after the PR #71 redeploy. Adding the explicit dep guarantees the import works regardless of langchain's transitive dep tree.

### Added

- **Engine telemetry collector hook — PR-prep-1 per `tapestry_canonical_framing_applied_2026_06_13`** (`services/skill_making/telemetry_collector.py`, `core/skill_making/compiler.py`, `core/runtime/runtime.py`, `services/api/main.py`, `services/skill_making/tenant_mapping.py`). Wires the runtime so every compiled-skill invocation emits a `TelemetryEvent` through the `telemetry_sender` shipped in PR #75 (which existed but was never called). New in-process collector with bounded asyncio queue (`MAX_QUEUE_DEPTH=10_000`) + background flusher (`BATCH_SIZE=100`, `FLUSH_INTERVAL_SECONDS=10.0`) + bounded shutdown drain (`SHUTDOWN_GRACE_SECONDS=5.0`). `compile_skill_to_tool` extended with `source_tenant_id` + `model_name` kwargs that are baked into each skill's `_run` closure — telemetry MUST NOT block the agent's response, so failures are caught + logged + swallowed. `AgentRuntime._resolve_agent` does an async reverse-lookup via the new `tenant_mapping.lookup_source_tenant(engine_tenant_id) -> source_uuid | None` helper once per cache miss; result is passed by kwarg into `_build_agent_from_config` (sync) so no ambient-context reads happen at invocation time. FastAPI lifespan starts the collector after `init_pool` and stops it before `close_pool`. **Tenants without a `tenant_id_mapping` row silently skip telemetry** (`source_tenant_id=None`) — skills still work; only observability degrades. Token counts extracted from langchain's `result.usage_metadata` (standard across Anthropic/OpenAI/Gemini per langchain_core's `BaseChatModel`). Privacy-bounded by `TelemetryEvent`'s `extra='forbid'`: only structural metadata. 6 new unit tests at `services/skill_making/tests/test_telemetry_collector.py` (lifecycle idempotence, batch flush, batch-size trigger, send-failure isolation, queue overflow). All 33 tests in `services/skill_making/tests/` pass locally (was 27 before this PR).

- **Wire-contract invariant tests at `services/skill_making/tests/`** — 27 pytest unit tests pinning the canonical `models.py` schema + the Stripe-style HMAC format. Catches the failure mode of the three spec-drift lessons by making schema/format changes loud at the test layer instead of silent until integration smoke. Two test files: `test_hmac_verify.py` (10 tests: valid/invalid signatures, timestamp window, secret mismatch, missing env var, signed-payload format with timestamp prefix) and `test_models_schema_invariants.py` (17 tests: non-nullable `tenant_id`, top-level `candidate_kind` + 9-kind taxonomy, `is_global` separate from `tenant_id`, `capability_tags` + `triggers` at top level not in frontmatter, `source.body_md` field name, `callbacks.telemetry` field name, `extra='forbid'` enforcement at every level, AckSkill + BridgeError + CompileOutcome enum exhaustiveness). Pure unit tests — no DB, no network. Run via `pytest services/skill_making/tests/`. All 27 pass at the time of this PR.

- **`GET /access/webhook/skill-promotion/versions`** endpoint (`services/api/main.py`) — schema-version discovery per wire-contract schema-versioning section. Returns `{"supported_versions": ["1.0"], "canonical": "1.0"}`. Lets the-loom (and any future bridge consumer) negotiate forward compatibility. Was missing from the engine; Loom-agent's audit caught it.

- **`services/skill_making/telemetry_sender.py`** — the third bridge message type per wire-contract section 3. `TelemetryEvent` + `TelemetryBatch` pydantic models + `send_telemetry_batch()` HMAC-signs (`X-MakeSkills-Signature` Stripe-style) and POSTs to `LOOM_TELEMETRY_CALLBACK_URL` (defaults to `loom-telemetry-ingestion.onrender.com/skill-used`). Same retry policy as `ack_sender` (3 attempts with exp backoff, no retry on 4xx). Privacy-bounded: structural metadata only — `skill_id`, `tenant_id` (source-side UUID, opaque), `outcome`, latency, token counts. NO user-message content, NO PII (enforced by pydantic `extra='forbid'`). Wiring from runtime invocation to this sender lives elsewhere and is a future PR; this module makes the send path callable from manual smoke or runtime collector when ready.
